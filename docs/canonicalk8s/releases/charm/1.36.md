# 1.36

**{{product}} Charms 1.36 - Release notes - Unreleased**

These notes cover what's changed in the `k8s` and `k8s-worker` Juju charms
since 1.35.

## Requirements and compatibility

The charms require Juju 3.3 or later and run on Ubuntu 24.04 LTS or
26.04 LTS on `amd64` and `arm64`. Use a Juju version that supports the
Ubuntu release you choose. Clusters can use managed or external etcd.
See the [charm installation guide] for deployment requirements.

## What's new

- **Kubernetes 1.36** - The charms install the {{product}} 1.36 snap.
  See the [upstream Kubernetes release notes] for changes to Kubernetes
  and the [1.36 snap release notes] for changes to bundled components.
- **Cilium service routing** - On new clusters that use the built-in
  Cilium network, Cilium now handles service traffic instead of `kube-proxy`.
  This is the default when `kube-proxy-enabled` is set to `auto`.
  Upgrades leave existing service routing in place. If you want to switch,
  see [how to enable Cilium service routing after upgrading] [#952].
- **Ubuntu 26.04 LTS** - You can now run control-plane and worker nodes
  on Ubuntu 26.04 LTS [#949].

## Also in this release

- The control-plane charm includes updated Grafana dashboards and Prometheus
  alert rules from kube-prometheus v0.18.0 [#984].
- Integrations using `kube-control` now receive `ghcr.io/canonical/cdk` as
  the image registry instead of `rocks.canonical.com/cdk`. If you restrict
  registry access, allow the new registry. This change was also backported
  to 1.35 [#976], [#981].
- The `system:cos` ClusterRole now grants only the permissions the
  observability integration needs. This change was also backported to 1.35
  [#873].
- This release updates the `kube-control` integration library and Python
  dependencies, including security fixes in `cryptography`
  [kube-control update], [#923].

## Deprecations and API changes

- **Ubuntu 22.04 LTS** - Neither charm nor its Terraform module supports
  Ubuntu 22.04 LTS in 1.36. Move your control-plane and worker units to
  a supported Ubuntu release before upgrading [#966].
- **`k8s-dqlite`** - The 1.36 snap no longer includes `k8s-dqlite`. You
  cannot upgrade a cluster that uses it, and there is no supported way
  to migrate the datastore [#861].
- **Terraform** - Both charm modules now require v1 or v2 of the
  Terraform provider for Juju. In each module call, replace `model` with
  `model_uuid` and pass the Juju model UUID instead of its name [#1013].
- For changes that may affect your workloads or clients, see the
  [upstream deprecations and API changes].

If you're upgrading an existing deployment, see the [1.36 upgrade checks]
before you refresh either charm.

## Fixed bugs and issues

- The `k8s` charm now applies `cluster-annotations` when you create a
  cluster and when you update its configuration. It keeps annotations
  you set outside Juju unless you set the same key in the charm. Use `-`
  as the value to remove an annotation. See [cluster annotation
  configuration] [#977].
- If the charm cannot apply node labels, the unit now reports `Waiting`
  instead of `Blocked` [#952].
- You can leave `expose` unset in the control-plane Terraform module
  without triggering a validation error [#1019].
