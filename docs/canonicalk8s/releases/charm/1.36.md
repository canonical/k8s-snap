# 1.36

**{{product}} Charms 1.36 - Release notes - Unreleased**

These notes cover the `k8s` and `k8s-worker` Juju charms.

## Requirements and compatibility

- Both charms run on Ubuntu 24.04 LTS and 26.04 LTS on `amd64` and `arm64`.
- The charms require Juju 3.3 or later. Use a supported Juju version that
  supports your chosen Ubuntu base. See the [charm installation guide].
- Clusters use managed or external etcd. See the [1.36 upgrade checks] if you
  are upgrading an existing deployment.

## What's new

- **Kubernetes 1.36**: the charms install the {{product}} 1.36 snap. See the
  [upstream Kubernetes release notes] and the [1.36 snap release notes] for
  Kubernetes and bundled component changes.
- **Cilium handles service routing on new clusters by default.** The `k8s`
  charm's new `kube-proxy-enabled` option defaults to `auto`: new clusters
  using the built-in Cilium network do not run `kube-proxy`, while upgrades
  preserve the existing service routing. To use a kube-proxy replacement
  on an existing cluster, see the [1.36 upgrade checks]. ([#952])
- **Ubuntu 26.04 LTS** is supported for control-plane and worker nodes.
  Ubuntu 24.04 LTS remains supported. ([#949])

## Also in this release

- The control-plane charm ships updated Grafana dashboards and Prometheus
  alert rules from kube-prometheus v0.18.0. ([#984])
- The image registry advertised over the `kube-control` relation is now
  `ghcr.io/canonical/cdk`, replacing `rocks.canonical.com/cdk`. Update registry
  allowlists if you restrict outbound access. This change was also backported
  to the 1.35 branch. ([#976], [#981])
- The `system:cos` ClusterRole grants only the permissions required by the
  observability integration. This change was also backported to 1.35. ([#873])
- Updated the `kube-control` relation library and Python dependencies,
  including security updates for `cryptography`. ([kube-control update], [#923])

## Deprecations and API changes

- **Ubuntu 22.04 LTS is no longer supported** by either charm or its Terraform
  module in 1.36. Move all control-plane and worker units to a supported base
  before refreshing. ([#966])
- **`k8s-dqlite` was removed.** The `bootstrap-datastore=dqlite` option is no
  longer available. Existing clusters using `k8s-dqlite` cannot upgrade to
  1.36, and there is no supported datastore migration. ([#861])
- **Terraform module inputs changed.** The `k8s` and `k8s-worker` modules now
  require the Juju Terraform provider v1 or v2. Replace the `model` input with
  `model_uuid` and pass the Juju model UUID instead of its name. Provider v0
  is no longer supported by these modules. ([#1013])
- See the [upstream deprecations and API changes] for changes that may affect
  Kubernetes workloads and clients.

## Fixed bugs and issues

- The `cluster-annotations` charm option now applies at bootstrap and on
  configuration updates. It preserves annotations set outside Juju unless you
  explicitly set the same key. Set an annotation's value to `-` to remove it.
  See [cluster annotation configuration]. ([#977])
- Units now report `Waiting` rather than `Blocked` when the charm cannot apply
  node labels. ([#952])
- The control-plane Terraform module no longer fails validation when its
  optional `expose` input is unset. ([#1019])
