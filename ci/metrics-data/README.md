# CI metrics data

Generated by `tox -e k8s-ci -- metrics ...` and by
`.github/workflows/ci-metrics.yaml`. Do not edit by hand.

## Why this branch exists

This branch is unprotected and triggers no workflows, which is what makes
automated commits possible at all.

Data cannot live on `main`. `main` is protected, so `GITHUB_TOKEN` cannot push
to it, and routing through a pull request is *circular*:
`lint_and_integration.yaml` only ignores `docs/**`, so a commit touching `ci/`
triggers the full build and e2e matrix, and automerge requires every check to
pass. At the current pass rate a daily metrics pull request would rarely merge
— the measurement system would be blocked by the very redness it exists to
measure.

The branch is cut from `main` rather than orphaned, so `git log`, `git diff`
and cherry-pick behave normally and the tree deltas against `main` instead of
storing a second full copy of it.

## Layout

| Path | Contents | Retention |
|---|---|---|
| `rollups/<YYYY-MM>.json` | aggregated metrics, one file per period | forever |
| `signatures/catalogue.json` | known failure signatures, updated in place | forever |
| `reports/` | rendered trend reports | forever |
| `runs/` | per-run records and evidence excerpts | 90 days, **artifact only** |

`runs/` is populated locally and uploaded as a workflow artifact. It is *not*
committed: at full volume it would add hundreds of MB per year to every clone
of a 14 MB repository. Committed data is roughly 1–3 MB per year.

## Retention and its consequence

`metrics reclassify` replays classification over stored excerpts, so it reaches
back only as far as the 90-day artifact window. That matches GitHub's own job
log retention, so nothing is really lost — the logs would be gone anyway.

Rollups keep the long-term trend regardless. Rollups older than the window are
frozen under the `ruleset_version` they were produced with, rather than being
retroactively rewritten. Comparing rollups across rule pack versions is
refused, because classifier churn would otherwise show up as CI improvement.

## Regenerating

Everything here is derived. To rebuild from scratch:

```sh
cd ci
tox -e k8s-ci -- metrics ingest --workflow nightly --since 90d
tox -e k8s-ci -- metrics fetch-logs --since 7d
tox -e k8s-ci -- metrics reclassify
tox -e k8s-ci -- metrics rollup
```
