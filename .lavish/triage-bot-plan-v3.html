    • 1 · One LangGraph workflow, grown in place

    A single compiled StateGraph. v1 wires only the triage-side nodes and routes straight to END after posting labels/comments. The reproduce/fix nodes are added later behind conditional edges — the graph, state, logging and CLI don't change shape.

    flowchart TD START([issue event / CLI --issue N]) --> ING[ingest
    fetch issue + comments via gh] ING --> PARSE[parse_inspect_tarball
    DETERMINISTIC · typed fields only] PARSE --> DEDUP[dedup_search
    embed + match open issues] DEDUP --> CLASSIFY[[classify — LLM
    kind/* area/* + missing-info?]] CLASSIFY --> GATE{enough info?} GATE -- "no" --> ASK[/post needs-info comment
    label · END/] GATE -- "yes" --> ROUTE[apply labels + route
    CODEOWNERS] ROUTE --> V1{{v1 stops here → END}} ROUTE -. "phase 2" .-> REPRO[[reproduce — LLM + probe
    self-hosted runner]] REPRO -. "confirmed" .-> TEST[[write e2e test
    fail on HEAD]] TEST -.     Solid = v1 (triage, ship first). Dotted = later phases added to the same graph. Double-bordered nodes call the LLM; the rest are deterministic Python.

    Deterministic first

    Ingest, tarball parse and dedup are plain Python. The LLM is only invoked to classify — cheap, and the rest stays testable without a model.

    Grown, not forked

    Adding reproduce/fix = add_node + one conditional edge. No new service, no second bot, no CLI reshuffle.

    Observable by construction

    Every node boundary emits a structured record via a LangGraph callback (§4). Same hook covers triage today and fix tomorrow.

    2 · State & node contracts

    State is a TypedDict. Each node returns a partial update; scalars are last-write-wins, accumulators use operator.add reducers (slupgrader's exact pattern). Every field an _-prefix is transient/non-serialised.

    TriageState (v1) + reserved fields

    # bot/state.py
class TriageState(TypedDict):
    # --- input ---
    issue_number: int
    issue_title: str
    issue_body: str          # SHA-pinned snapshot
    issue_body_sha: str
    # --- deterministic derived ---
    inspect_fields: dict      # typed, parsed tarball
    dedup_candidates: list[dict]
    # --- classify (LLM) ---
    kind_labels: list[str]
    area_labels: list[str]
    missing_info: list[str]
    # --- outcome / metrics (reducers) ---
    actions_taken: Annotated[list[str], operator.add]
    prompt_tokens: Annotated[int, operator.add]
    completion_tokens: Annotated[int, operator.add]
    outcome: str            # routed|needs_info|duplicate
    # --- reserved for phase 2/3 (unused in v1) ---
    repro_confirmed: NotRequired[bool]
    generated_test: NotRequired[str]
    fix_changes: NotRequired[list[str]]

    Node contract

    • Signature: def node(state) -> dict. Pure w.r.t. state; side effects (gh calls) are explicit and mockable.
    • Determinism: ingest, parse_inspect_tarball, dedup_search take no LLM. Unit-testable with zero setup.
    • LLM nodes return a token delta so the reducers total run cost automatically.
    • Routing via add_conditional_edges on observable state (outcome, missing_info), never on model internals.
    • Validation seam: a validated_node(name, fn) wrapper (from slupgrader) runs post-conditions in tests/CI; zero overhead in prod.
    Graph build uses the verified 1.x API: StateGraph(TriageState) → add_node / add_edge / add_conditional_edges with START/END from langgraph.graph, then .compile().

    3 · Provider-agnostic LLM (Gemini first)

    One knob switches provider. We use LangChain's built-in init_chat_model (verified present in langchain 1.3.11 with a google_genai provider), wrapped in a tiny factory so the graph never imports a vendor SDK directly.

    The whole abstraction

    # bot/llm.py  — one factory, provider-agnostic
from langchain.chat_models import init_chat_model

DEFAULT_MODEL = "google_genai:gemini-2.5-flash"

def make_llm(model_spec: str = DEFAULT_MODEL, **kw):
    # "provider:model" — one string picks everything
    return init_chat_model(model_spec, temperature=0, **kw)

    Switching provider is pure config: google_genai:gemini-2.5-flash → anthropic:claude-... → openai:gpt-.... Each reads its own env key (GOOGLE_API_KEY for Gemini, verified).

    Why init_chat_model over a hand-rolled dispatch

    • Built into langchain — no bespoke if provider == ... ladder to maintain (slupgrader predates it; we don't need to).
    • configurable_fields lets one compiled graph swap models per-invocation for A/B or per-node tiers (cheap classify vs. stronger fix).
    • Structured output via .with_structured_output(PydanticModel) for the classify node — typed labels, no brittle JSON parsing. (Gemini caveat: a few JSON-schema keys like additionalProperties are dropped; benign, we keep schemas flat.)
    • Secrets come from env only, never CLI flags (slupgrader convention).

    4 · Structured logging (slupgrader + one improvement)

    slupgrader is a strong architectural precedent but a weak logging one: stdlib logging to stderr with a manual [node] string prefix, and no run_id/node_id on records — you can't isolate one run from the logs. Real per-node structure is delegated to opt-in Langfuse/OTEL. We copy the good parts and fix the gap.

    The seam: one callback = one record per node + per LLM/tool

    # bot/logging.py — VERIFIED: on_chain_start fires once
# per node with metadata["langgraph_node"] set.
class RunLogger(BaseCallbackHandler):
    def __init__(self, run_id, sink):
        self.run_id, self.sink = run_id, sink
    def on_chain_start(self, serialized, inputs, **kw):
        node = (kw.get("metadata") or {}).get("langgraph_node")
        if node:
            self.sink({"run_id": self.run_id, "node": node,
                       "event": "node_start", "ts": now()})
    def on_llm_end(self, response, **kw):
        # tokens nest UNDER the active node span
        self.sink({"run_id": self.run_id, "event": "llm_end",
                   "tokens": usage(response)})

    Passed via app.invoke(state, config={"callbacks":[RunLogger(...)], "run_name":..., "metadata":{...}}). Proven on langgraph 1.2.7: callbacks saw ['triage','reproduce'] in order.

    What we ship

    • Human sink: stdlib logging to stderr, slupgrader's format, plus a run_id+node filter so every line is attributable.
    • Machine sink: newline-delimited JSON record per node/LLM/tool event → queryable offline, no hosted UI needed. This is the gap slupgrader left.
    • Run artifact: one run-<id>.json summary (outcome, per-node timings, tokens, actions) written next to the CLI — mirrors slupgrader's .llm-fix-results.json.
    • Redaction: port CredentialRedactor — known secret values → [REDACTED:KEY] before anything is logged.
    • Opt-in tracing: Langfuse/OTEL handlers as packaging extras; appended to the same callbacks list when env is set. Base install stays lean.
    • Noise control: port _silence_noisy_loggers() (httpx / langchain_google_genai._function_utils).

    One seam, many sinks

    flowchart LR GRAPH[LangGraph run
    app.invoke] --> CB[[RunLogger
    callback handler]] CB --> RED[CredentialRedactor
    REDACTED:KEY] RED --> HUMAN[stderr
    run_id + node prefix] RED --> JSON[(ndjson

    The callback is the single attach point. Redaction runs before any sink; JSON + run summary are always on, hosted tracing is an opt-in extra on the same callbacks list.

    5 · Integration into ci/k8s-ci.py

    The bot is a new subcommand group, following the repo's exact pattern: add_<group>_cmds(subparsers) → p.set_defaults(func=cmd_*), each cmd_*(args)->int. Nothing about the existing CLI changes.

    Wiring + invocation

    # ci/k8s-ci.py — one added line
from cmds.triage import add_triage_cmds
add_triage_cmds(subparsers)

# ci/cmds/triage.py
def add_triage_cmds(subparsers):
    p = subparsers.add_parser("triage", help="issue triage bot")
    sub = p.add_subparsers(required=True)
    r = sub.add_parser("run")
    r.add_argument("--issue", type=int, required=True)
    r.add_argument("--model", default="google_genai:gemini-2.5-flash")
    r.add_argument("--dry-run", action="store_true")  # no gh writes
    r.add_argument("--from-fixture")                # local JSON, no network
    r.set_defaults(func=cmd_triage_run)

    Run it three ways

    # CI (GitHub Actions)
tox -e k8s-ci -- triage run --issue 1234

# Local, real issue, no writes
tox -e k8s-ci -- triage run --issue 1234 --dry-run

# Fully offline from a saved fixture
tox -e k8s-ci -- triage run \
  --from-fixture tests/fixtures/issue_dns.json --dry-run
    • --dry-run mirrors the repo-wide convention: compute everything, print the planned labels/comment, write nothing.
    • --from-fixture feeds a saved issue payload → reproducible local runs, the seed corpus for eval.
    • Deps land in a new ci/requirements-triage.in extra so the base k8s-ci stays stdlib-light.

    6 · Local + offline testing

    The whole graph runs deterministically with zero LLM/network by injecting a fake chat model — slupgrader's exact test strategy, on the verified 1.x fake classes.

    Deterministic graph test

    # VERIFIED: FakeMessagesListChatModel CYCLES
# (GenericFakeChatModel exhausts → StopIteration).
from langchain_core.language_models.fake_chat_models \
    import FakeMessagesListChatModel

def test_triage_routes_dns_issue(monkeypatch):
    fake = FakeMessagesListChatModel(responses=[
        AIMessage(content='{"kind":["bug"],'
                            '"area":["network"]}')])
    monkeypatch.setattr("bot.llm.make_llm", lambda *a, **k: fake)
    state = run_triage(load_fixture("issue_dns.json"),
                       dry_run=True)
    assert state["outcome"] == "routed"
    assert "area/network" in state["area_labels"]

    Test layers

    • Deterministic nodes (parse, dedup, routing) — plain unit tests, no fakes needed.
    • Graph flow — inject the fake model, assert routing/labels/outcome. Marks: fast + offline, default suite.
    • gh boundary — a thin GitHubClient mocked like slupgrader's FakeBackend; --dry-run asserts zero writes.
    • Live (marked slow) — real Gemini + real issue, credential-gated, excluded from default pytest.
    • Runs under the repo's flake8/black/isort/bandit tox envs unchanged.

    7 · Extensibility path to reproduce/fix

    The v2 findings (decoupled probe oracle, cross-repo build reality, honest cost) still hold — they now become later nodes in this graph, gated by conditional edges. Adding them is additive.

    • Triage nodes
      classify + route + needs-info. Ship, measure time-to-first-action.
    • reproduce node
      deterministic probe on a self-hosted LXD runner; confirm symptom before any test.
    • write-test node
      e2e test that fails on HEAD, asserts against probe signal.
    • fix + verify nodes
      bounded LLM repair loop; draft PR (+ cross-repo staged drafts).
    Because reproduce/fix are the expensive, risky part, they stay behind a maintainer bot:fix label and a self-hosted runner — the graph simply doesn't route there until the label and phase are enabled. State fields for them are already reserved (§2), so no migration.

    8 · Security carry-over (still binding)

    The adversarial review from v2 still governs — even the triage-only v1 reads attacker-controlled text (issue body, comments, tarball logs). These are cheap to honour now and prevent a redesign later.

    Tarball / log injection

    Deterministic parse to typed fields; the LLM classify node sees only the struct, never raw log text. No tools bound on the classify model.

    Issue-edit race

    SHA-pin issue_body at event time (state field already present); never re-fetch mid-run.

    Least privilege

    v1 token scope: issues:write (labels/comments) only. No contents/PR scope until the fix phase. Bot machine account, not a human PAT.

    Auto-merge firewall

    When PRs arrive (phase 3): bot:generated + no-backport on the repo's auto-merge/backport exclusion lists. Draft-only.

    9 · Rollout

    • step 1
      Scaffold + triage graph
      ci/cmds/triage.py, bot/ package (state, llm, logging, nodes, graph), fixtures, offline tests. Deterministic nodes + classify. --dry-run / --from-fixture working locally.
    • step 2
      Shadow in CI
      Workflow on issues:[opened,edited], comment-only (or label-only) mode. Structured JSON run-logs collected. Gate: sane labels on ≥50 real issues, time-to-first-action baseline captured.
    • step 3
      Live triage
      Real labels + needs-info comments. Provider still swappable. Only after this proves out do we open the reproduce node behind bot:fix.
    • step 4+
      reproduce → test → fix nodes
      Added to the same graph on self-hosted runners, draft-PR-only, per the v2 oracle/cost findings. Each is its own gated increment.
